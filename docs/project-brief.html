ReadAloud

Oral reading fluency assessment that runs entirely on a teacher's laptop.

Start here, if you know nothing about this

In primary school, teachers regularly check how well each child can read out loud. The standard method is called a running record. The teacher sits one to one with a child, the child reads a short passage aloud for about a minute, and the teacher marks every word that goes wrong: words misread, words skipped, words added, words the child corrected on their own.

From those marks the teacher works out a score. How many words per minute the child read correctly, what percentage of the passage was accurate, and whether this text is at the right level for them. It is one of the most informative minutes in early education, and it is done for every child, several times a year.

ReadAloud does the marking. The child reads into a laptop. Speech recognition runs on that laptop, the software compares what it heard against the passage the child was given, classifies every difference, and produces the same running record a teacher would have written by hand. Nothing is uploaded. There is no account, no subscription, and no internet connection required once it has been set up.

The one sentence version. A child reads aloud for a minute, the laptop scores it the way a trained teacher would, and no recording of that child's voice ever leaves the room.

The problem it addresses

Time

A class of 28 children, assessed three times a year, is 84 individual sessions. Each one is roughly a minute of reading and several more minutes of tallying and arithmetic. The tallying is the part that consumes the teacher, and the other 27 children are unsupervised while it happens.

Consistency

Two teachers scoring the same recording will not always agree. Whether a hesitation counts, whether a self correction counts, whether a mispronunciation is a decoding error, all vary between scorers and between the same scorer on different days. A child's record partly reflects who held the pencil.

Privacy

Existing automated tools send the audio to a vendor's servers. That means recordings of children's voices, often children already identified as struggling readers, leaving the school and accumulating in a third party's storage. Districts have to weigh that against the benefit.

Cost and access

Commercial reading assessment platforms are licensed per student per year. Schools with the least funding, which are frequently the schools with the most struggling readers, are the least able to buy them.

How it works

The key idea is that this is not transcription, it is alignment. A general speech recogniser has to decide which of roughly forty thousand English words it just heard. ReadAloud already knows what the passage says, so it only has to decide how what it heard differs from about a hundred known words. That is a far smaller and far more tractable problem, and it is why the system can be accurate without a large model.

StageWhat happens
RecordBrowser captures the audio at 16kHz mono. A live input meter shows the microphone is working, because a dead mic is otherwise invisible until it is too late.
TranscribeOpenAI's Whisper model, converted to run in the browser, produces a transcript with a timestamp for every word. This runs on the device, in a background thread.
AlignThe Needleman-Wunsch algorithm, borrowed from bioinformatics, finds the best correspondence between what was heard and what was written. It handles insertions, deletions and substitutions in one pass.
ClassifyEach difference is labelled: substitution, omission, insertion, self correction or repetition. Repetitions and self corrections are not errors, per standard running record convention.
FilterFour filters decline to score things that are not reading errors: homophones, dialect features, near identical spellings, and phonetic near misses. Every one is recorded and shown.
ReportWords correct per minute, accuracy, self correction rate, instructional level, percentile band against published norms, and a printable one page record.

What makes it different

1. There is no language model in it, so it cannot make things up.

Whisper converts sound to text and nothing else. Everything after that is a sequence alignment algorithm and a rule set drawn from the literacy assessment literature. The same audio always produces the same score. In a tool that influences how a child is placed, a system that cannot be reproduced is not a measurement, it is an opinion.

2. No API key, no account, no server, no subscription.

The entire application is a static website. There is no backend to operate, nothing to log into, no per student licence, and no ongoing cost of any kind. It has been verified running with every external network host blocked: record, transcribe, score and print all completed with zero outbound requests. A school can put it on a USB stick.

3. It shows its uncertainty instead of hiding it.

Words are green, red, or amber. Amber means the system heard something different but is not confident enough to call it an error, so it does not. Every amber word is listed with the specific rule that forgave it. A tool that silently forgives is making a claim it never shows you.

4. The teacher can overrule it in both directions.

Any flagged word can be marked correct, and any forgiven word can be counted as an error. That second direction is unusual and it matters: four filters in this system can only ever remove errors, so if the only control were the power to forgive, every adjustment the tool offered would push a child's score upward.

5. It measured its own headline feature and published a failure.

See the next section. This is the thing that most distinguishes the project, and it is not a feature at all.

The finding that defines the project

The most ambitious part of ReadAloud is a dialect sensitive layer. Miscue analysis has a long documented history of scoring dialect features as reading errors, which systematically mislabels fluent speakers of African American English as struggling readers. Speech recognisers compound it: Koenecke et al. (PNAS, 2020) measured roughly double the word error rate for Black speakers across all five major commercial systems. So the layer encodes linguistic rules that refuse to score a dialect consistent pronunciation as a mistake.

Then we measured whether it ever activates. Across the entire evaluation, it fired zero times.

The reason is structural. Whisper is trained to produce standard spelling, so it rewrites the dialect features into standard forms before our rules can ever see them. aksed becomes asked. wif becomes with. sista becomes sister. The layer is looking for something that has already been erased.

What the measurement found instead is larger. Where Whisper does not normalise, it mis-segments. Spoken "dis col" comes back as Diskal. "fo fo" comes back as Fofo. Two words fuse into one, or one splits into two. Scored end to end, a dialect speaking reader is charged five errors on a twelve word passage. That is a real, quantified bias, and no rule about pronunciation can reach it, because the damage is to the word boundaries rather than to the words.

We published the zero, explained the mechanism, and reduced the claim to the part that survives: the equity contribution is the architecture, not the rule table. Aligning against a known hundred word passage collapses the recognition problem enough to absorb most accent driven error structurally. And no child's voice leaves the device.

Five passages, fifty deliberately planted miscues. Ground truth is constructed, not annotated: the spoken text is generated from the reference by applying an explicit error script, so the correct answer is known with certainty and there is no labelling step to disagree with. A detection only counts if it flags the same position with the same type.

The false positive rate is the number that was optimised, and it is the one to lead with. Telling a child who read correctly that they made a mistake is a worse failure than missing an error, and those two do not trade off evenly in a classroom.

Strengths

  • Cannot hallucinate. No generative model anywhere in the scoring path. Deterministic and reproducible.
  • Complete privacy. No audio or transcript leaves the machine, verified empirically under network denial, not merely claimed.
  • Zero marginal cost. No licence, no per student fee, no API billing. Runs on hardware schools already own.
  • Works offline. After a one time model download, no connectivity is needed. Relevant for rural schools and locked down networks.
  • Auditable. Roughly 1,500 lines of readable, tested, cited scoring logic. Every suppression names the rule that caused it. A district can inspect exactly why a child received a score.
  • Norms verified at source. Every figure checked digit by digit against Hasbrouck & Tindal (2017). Two of the six commonly quoted spring medians turned out to be circulating in an outdated form.
  • Honest about uncertainty. Percentiles are reported as bands, never point estimates. Below the published floor reports "below 10th" rather than inventing a number. Grades without published norms report none.
  • Refuses to score bad input. Silence, a dead microphone, a recorder left running, or a recogniser hallucination are all detected and refused rather than turned into a confident report.
  • Accessible by design. Colour never carries meaning alone, every mark also has a glyph and an underline style so it survives greyscale printing and colour vision deficiency. Dyslexia friendly font stack, three text sizes, high contrast, full keyboard navigation.
  • Covers K to 12. Sixty five original passages, five per grade, length scaled to what a reader at that level covers in a minute.

Limitations, stated plainly

  • It has never been tested on a child's voice. Every evaluation clip is speech synthesis, one adult voice reading faster than the 90th percentile for grade six. A seven year old at 60 words per minute with real pauses and false starts will behave differently. This is the single largest unknown in the system.
  • The evaluation conflates two things. Against text alone the scorer recovers its own ground truth at 100% precision and 92% recall. The gap between that and the published table is Whisper on synthetic speech. The reported numbers describe the pair, not the alignment layer alone.
  • The planted errors are the easy ones. Real child substitutions are phonologically close, like house and horse, which is exactly where a suppression stack is most likely to forgive them.
  • Self correction recall is 40% by construction. A purely semantic self correction is indistinguishable from an added word without a language model, and there deliberately is not one.
  • The dialect layer does not currently fire. Documented above. It is reported rather than hidden, but it is a feature that does not presently do work.
  • Published norms stop at grade 6. Older students receive accuracy and words per minute, but any percentile refers to the passage's grade rather than their own.
  • No persistence. Nothing is saved between sessions, so there is no progress tracking, no class view and no history. That is a deliberate privacy choice with a real usability cost.
  • No roster integration. Students are a hardcoded list. A real deployment would need to sync from an existing system.
  • Desktop only, 1024px and up, and Chromium based browsers for the speech model.
  • It is a screening aid, not a validated instrument. The path to becoming one is an inter rater reliability study against certified human scorers, stratified by dialect, on at least a hundred real child readers. That is a semester of work.

Real world application

The immediate case: universal screening without funded staff time

Most US states now mandate universal early literacy screening in the primary grades. The mandate rarely arrives with funded staff time to carry it out, so the work falls on classroom teachers who are already teaching. ReadAloud does not remove the need for a teacher to be present, and it should not be sold as though it does. What it removes is the tallying and the arithmetic, and it applies identical rules to every child every time. A district gets a consistent record without buying a licence and without shipping recordings of children off site.

Where the design matters most

Schools with restricted connectivity

Rural districts and buildings with heavily filtered networks cannot rely on a cloud service during a lesson. This runs with the wifi off.

Districts with strict data policies

Where student voice recordings cannot legally or politically leave the building, an on device tool is not a preference, it is the only option available.

Adult literacy and correctional education

Adult learners are frequently more sensitive about being recorded than children are. A tool that provably retains nothing changes what is possible in that setting.

Progress monitoring, not just benchmarking

A teacher who can score a read in fifteen seconds can check a struggling reader weekly rather than three times a year. That is a change in what is possible, not a 30% efficiency gain, and it is the strongest honest claim available.

A reference implementation for auditable assessment

Commercial equivalents are black boxes a district cannot inspect. This is readable, tested, cited scoring logic. Even where it is not deployed, it demonstrates that an assessment tool can be built so that every decision it makes is explainable.

How to present it

Build the talk around a reversal. An audience expects a pitch to escalate its claims. This one retracts one, and gets stronger for it. That is what makes people pay attention.

TimeWhat you do
0:00Open on a child, not a statistic. One specific second grader who gets sixty seconds of reading assessed while a teacher makes tick marks. No slide yet. Talk to the room.
0:20Turn the wifi off, visibly, on stage. Then hand the microphone to a judge and ask them to read the passage. Say nothing at all while they read. This is the strongest twenty seconds you have and it is demonstrated rather than claimed.
1:10Point at amber. Green correct, red miscue, amber not confident enough to call it. Then click a forgiven word and count it as an error. Every number recomputes.
1:50The reversal. Introduce the dialect layer as the headline feature, then say it fired zero times. Pause. Do not fill the silence. Then explain why, and give the larger finding underneath it.
2:30One number. 0.48% false positives on clean reads, and why that is the metric that was optimised.
2:45Hand a judge the printed report. Physical paper at a software demo is disproportionately memorable. Then stop talking.

Questions you will be asked, and the answers

QuestionAnswer
How is this different from ChatGPT?There is no language model in it. It aligns audio against a known text and applies a rule set from the literacy assessment literature. It cannot invent anything.
So your main feature doesn't work?It does not fire on this data, and we published that rather than shipping something we could not defend. What it found instead is a bias no rule table can fix, which is a more useful result.
Does it work on children's voices?We do not know, and we will not pretend otherwise. Whisper is trained predominantly on adult speech. Aligning against known text helps considerably, and uncertain cases surface as amber rather than red. Testing on real children is the next step.
What about accents and multilingual learners?Structurally the alignment approach absorbs a great deal of accent driven recognition error. The explicit dialect rules do not currently fire, for the reasons in the evaluation. Both statements are in our written report.
Could a school actually use this?Today it is a prototype. The path to deployment is a validation study against human scorers, which is a semester of work, not a weekend.
Where is the AI?A 74 million parameter speech model running locally, plus a sequence alignment algorithm, plus a rule based linguistic filter. The deterministic components were chosen deliberately: in a tool affecting a child's placement, non reproducible output is a defect.

Two things not to do

Do not claim large time savings. The teacher still has to sit with the child. What is saved is the tallying and the arithmetic, and an inflated figure invites the one question that undermines the pitch. Do not cite IDEA transition planning requirements. Those concern postsecondary transition at age 16 and have nothing to do with primary reading fluency. Judges who know the legislation will notice, and it would cost you every other number on the slide.

Algorithms and scoring logic, all hand written

AlgorithmWhat it does here
Needleman-WunschGlobal sequence alignment, originally from bioinformatics. Builds the full dynamic programming matrix over the passage and the transcript, then backtraces to produce an operation list. Ties are broken toward the diagonal, which biases toward calling a deviation a substitution rather than an omission plus an insertion, matching how a human marks a running record.
Levenshtein distanceEdit distance, used for the fuzzy filter and for detecting partial word self corrections. Implemented with a two row rolling buffer.
SoundexPhonetic hashing, so words that sound alike can be recognised as recogniser noise rather than reading errors. Gated hard, because Soundex alone is far too permissive.
Morphological lemma matchingWritten for this project. Detects when one word is another plus a regular inflection, so a dropped plural or tense marker can never be forgiven as a phonetic coincidence.
Text normalisationNumber to word expansion including ordinals and decimals, contraction expansion, diacritic folding, disfluency stripping, and removal of the specific phrases Whisper hallucinates onto trailing silence.
Dialect rule engineSeven guarded phonological rules: th stopping, th fronting, postvocalic r lessness, final devoicing, consonant cluster reduction, g dropping, and metathesis. Each carries guards preventing it from erasing genuine morphology.

Assessment methodology, from the literature rather than invented

  • Running record conventions (Clay) for what counts as an error. Repetitions and self corrections are not errors; substitutions, omissions and insertions are.
  • Hasbrouck & Tindal 2017 ORF norms for percentile bands, transcribed digit by digit from the primary source rather than a secondary table.
  • Instructional level bands at 95% and 90% accuracy, standard convention.
  • Two different error counts, because words correct per minute and accuracy are defined differently. Insertions count toward accuracy following Clay, but not toward the rate, because the norm setting procedure does not score them.

Accessibility implementation

  • WCAG AA contrast throughout, and colour never used as the sole carrier of meaning. Every marked word also has a glyph and a distinct underline style.
  • Semantic HTML with correct heading order, ARIA landmarks, and aria-describedby on every marked word so a screen reader announces the explanation on focus.
  • Dyslexia friendly typography as a font stack rather than a downloaded webfont, so the accessibility toggle keeps working with no network.
  • Three text sizes, high contrast mode, complete keyboard navigation, visible focus rings, and prefers-reduced-motion honoured.
  • A dedicated print stylesheet producing a one page record that survives a monochrome printer.

What is deliberately absent

No backend of any kind. No database. No authentication. No analytics or telemetry. No language model. No component library. No CSS framework beyond Tailwind. No state management library. No router. No webfonts. No content delivery network at runtime. Every one of those omissions is a decision rather than an oversight, and each removes a failure mode from a tool that has to work in a classroom with no network and no technician.
